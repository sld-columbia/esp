# ESP Toolchain Build Fixes for Modern glibc (>= 2.33)

The Buildroot version (`d6fa6a45e1`) used by `build_riscv_toolchain.sh` and
`build_leon3_toolchain.sh` ships host tools that are incompatible with
glibc >= 2.33 (Ubuntu 22.04+, etc.). The following issues were identified and
fixed.

## Supported Platforms

The RISC-V toolchain build script has been tested on:
- **Ubuntu 18.04** (glibc 2.27) — no patches needed, all fixes are harmless no-ops
- **Ubuntu 22.04** (glibc 2.35) — all patches and fakeroot swap applied automatically
- **RHEL 7/8** (glibc 2.17/2.28) — no patches needed
- **RHEL 9** (glibc 2.34) — all patches and fakeroot swap applied automatically

### Prerequisites on glibc >= 2.33 systems

On Ubuntu 22.04+, RHEL 9, or any system with glibc >= 2.33, the `fakeroot`
system package must be installed. The script detects this and exits with
install instructions if it is missing:
```
Ubuntu/Debian: sudo apt-get install fakeroot
RHEL/CentOS:   sudo yum install fakeroot  (requires EPEL)
```

## Shared Issues (RISC-V and Leon3)

### Issue 1: Buildroot `.br-external.mk` missing after `make distclean`

**Symptom:**
```
make[1]: *** No rule to make target '.../buildroot/output/.br-external.mk'. Stop.
```

**Root cause:**
`make distclean` removes `output/.br-external.mk`, and the Makefile tries to
include it before it can be regenerated by `make defconfig`. Additionally,
`make distclean` itself fails if the file is missing when it starts.

**Fix:**
Create an empty `output/.br-external.mk` **before and after** `distclean`:
```bash
mkdir -p output && touch output/.br-external.mk
make distclean
mkdir -p output && touch output/.br-external.mk
```

### Issue 2: `host-fakeroot-1.20.2` — `_STAT_VER` undeclared

**Symptom:**
```
libfakeroot.c:99:40: error: '_STAT_VER' undeclared
```

**Root cause:**
glibc 2.33 removed the `__xstat()` family of functions and the associated
`_STAT_VER`, `_STAT_VER_KERNEL`, `_STAT_VER_GLIBC2`, and `_STAT_VER_GLIBC2_1`
macros. fakeroot 1.20.2 relies on these to wrap stat/mknod syscalls.

**Fix:**
Patch `libfakeroot.c` and `communicate.c` with fallback `#ifndef` definitions
for the removed macros. The patch file `patches/host-fakeroot-glibc-compat.patch`
is copied into `package/fakeroot/0003-fix-stat-ver-glibc-2.33.patch` in the
buildroot tree before `make`, so buildroot applies it automatically during
source extraction.

### Issue 3: `host-m4-1.4.18` — `SIGSTKSZ` not a compile-time constant

**Symptom:**
```
c-stack.c:55:26: error: missing binary operator before token "("
   55 | #elif HAVE_LIBSIGSEGV && SIGSTKSZ < 16384
```

**Root cause:**
glibc 2.34 changed `SIGSTKSZ` from a compile-time constant to a runtime
function call (`sysconf(_SC_SIGSTKSZ)`). The `#elif` preprocessor directive
in m4's `c-stack.c` cannot evaluate a function call.

**RISC-V fix:**
Unconditionally `#undef SIGSTKSZ` and `#define SIGSTKSZ 16384`.
The patch file `patches/host-m4-sigstksz.patch` is copied into
`package/m4/0003-fix-sigstksz-glibc-2.34.patch` in the buildroot tree before
`make`, so buildroot applies it automatically during source extraction.

**Leon3 fix:**
The patch file does not apply cleanly to the Leon3 buildroot's version of
`c-stack.c` (context mismatch). Instead, an in-place `sed` replaces the
problematic `#elif` with `#elif 0` so the expression is never evaluated:
```bash
sed -i 's/^#elif HAVE_LIBSIGSEGV && SIGSTKSZ < 16384/#elif 0 \/* SIGSTKSZ not constant on glibc >= 2.34 *\//' "$f"
```

### Issue 4: `fakeroot` fails to intercept `mknod` at runtime

**Symptom:**
```
mknod: .../dev/console: Operation not permitted
```
during the final rootfs image generation step.

**Root cause:**
Even after patching fakeroot to compile, the `__xmknod` wrapper that fakeroot
uses to intercept `mknod()` calls no longer exists in glibc >= 2.33. The
compiled fakeroot reports `uid=0` but cannot actually fake device node creation.

**Fix (RISC-V):**
The script detects the glibc version at build time. On glibc >= 2.33, it builds
fakeroot first (`make host-fakeroot`), then replaces it with the system-installed
`/usr/bin/fakeroot` (a newer version that uses different interception mechanisms)
before continuing the full build:
```bash
GLIBC_VER=$(ldd --version 2>&1 | head -1 | grep -oE '[0-9]+\.[0-9]+$')
if [ "$(printf '%s\n' "2.33" "$GLIBC_VER" | sort -V | head -1)" = "2.33" ]; then
    make host-fakeroot -j ${NTHREADS}
    mv output/host/bin/fakeroot output/host/bin/fakeroot.buildroot
    ln -s /usr/bin/fakeroot output/host/bin/fakeroot
fi
make -j ${NTHREADS}
```
This approach is deterministic — no retry loops or error detection needed.
If the system `fakeroot` is not installed, the script exits with clear
install instructions.

**Fix (Leon3):**
The Leon3 script uses a retry loop with runtime detection as its buildroot
version differs.

## Leon3-Only Issues

### Issue 5: GCC 5.5.0 `bool++` forbidden in C++17

**Symptom:**
```
reload1.c:115:24: error: use of an operand of type 'bool' in 'operator++' is forbidden in C++17
```

**Root cause:**
The Leon3 toolchain builds GCC 5.5.0 as a host tool (the cross-compiler for
SPARC). GCC 5.5.0's `gcc/reload.h` declares `bool x_spill_indirect_levels;`
and `reload1.c` uses `spill_indirect_levels++` on it. Ubuntu 22.04's host
GCC 11+ defaults to C++17, where `operator++` on `bool` is illegal.

This does **not** affect the RISC-V toolchain because it uses a newer GCC
version that does not have this issue.

**Fix:**
Change `bool` to `char` in the declaration (both types are single-byte and
the variable is used as a small counter):
```bash
for f in output/build/host-gcc-initial-*/gcc/reload.h \
         output/build/host-gcc-final-*/gcc/reload.h; do
    if [ -f "$f" ] && grep -q 'bool x_spill_indirect_levels' "$f"; then
        sed -i 's/bool x_spill_indirect_levels/char x_spill_indirect_levels/' "$f"
        rm -f "$(dirname "$f")/../build/gcc/reload1.o" 2>/dev/null
    fi
done
```
The stale `reload1.o` is deleted to force a rebuild with the patched header.

### Issue 6: Buildroot clone URL unreachable

**Symptom:**
```
fatal: unable to access 'https://git.buildroot.net/buildroot/': Connection timed out
```

**Root cause:**
The original Leon3 script cloned from `git.buildroot.net`, which is
intermittently unreachable. The RISC-V script already used the GitHub mirror.

**Fix:**
Changed clone URL to `https://github.com/buildroot/buildroot.git` in both
the Leon3 and RISC-V scripts.

## Kernel Build Fixes (Ariane)

These are not toolchain-build issues — they affect the Linux kernel build
itself (`make linux` for Ariane). They live alongside the toolchain patches
because they share the same root cause family (newer host toolchain breaking
older vendored sources), and `utils/make/ariane.mk` applies them on demand
before the kernel build starts.

### Issue 7: kernel `dtc` fails to link on GCC >= 10

**Symptom:**
```
ld: scripts/dtc/dtc-parser.tab.o:(.bss+0x0): multiple definition of `yyloc';
    scripts/dtc/dtc-lexer.lex.o:(.bss+0x0): first defined here
```
when running `make linux` on Ubuntu 22.04, RHEL 9, or any host with GCC 10+.

**Root cause:**
GCC 10 changed the default for tentative definitions from `-fcommon` to
`-fno-common`. The Ariane Linux kernel ships an older in-tree `dtc` whose
lex/yacc-generated globals (`yyloc`, etc.) rely on the old behaviour. Upstream
fixed this in v5.7+, but the vendored kernel here predates the fix.

**Fix:**
`patches/linux-dtc-fcommon.patch` adds `-fcommon` to `HOSTCFLAGS_dtc-lexer.lex.o`
and `HOSTCFLAGS_dtc-parser.tab.o` in `scripts/dtc/Makefile`. The patch is
applied by the `linux-patches` make target in `utils/make/ariane.mk`, which
runs as an order-only prerequisite of the kernel `.config` step. The rule is
idempotent — it greps for `-fcommon` and skips if already present, so it is
safe to run on any host (no-op on GCC < 10 builds where the patch has already
been merged into the working tree, or on resubmodule-init).

## How Patches Are Applied (RISC-V)

The RISC-V script copies patch files into buildroot's own `package/` directories
**before** running `make`. This way buildroot applies them natively during source
extraction — no fail-retry logic needed:

```
patches/host-m4-sigstksz.patch        → package/m4/0003-fix-sigstksz-glibc-2.34.patch
patches/host-fakeroot-glibc-compat.patch → package/fakeroot/0003-fix-stat-ver-glibc-2.33.patch
```

The patches are harmless on older glibc (guarded by `#ifndef` / `#undef`).
